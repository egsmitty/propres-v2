## The save model (plan A5, merged 2026-09-09) — read before touching saves

`tasks/plan-A5-autosave.md`. Three concepts, one rule:

| Concept | Lives in | Changed by |
|---|---|---|
| Live document | the `presentations` row | autosave, save, revert |
| Versions (restore points) | `presentation_versions` (migration 5) | manual save, open-if-none, create |
| In-memory document | `useEditorStore.presentation` | every edit |

**`isDirty` means "the live row differs from the newest version", and autosave
never clears it.** Only Save (which appends a version) and Revert (which moves
the row back) may. `File ▸ Revert to Last Save` and the Unsaved Changes dialog's
Discard both revert. Versions are append-only, pruned to 25 per presentation,
and **newest is `id DESC`, never `saved_at`** — `unixepoch()` is
second-resolution and two saves in one second would tie.

The A2 crash-recovery journal's **writer is gone**: every autosave bumps
`updated_at`, so `selectRecoverable` would call every journal row stale before
reading it. The table, the migration and `offerRecoveryOnStartup` remain to
drain profiles written by older builds; they can go once none have rows.

**Why it looks the way it does:** Ethan's product thesis, stated 2026-09-09 —
*mirror successful apps in almost everything; spend the novelty budget only on
church-service focus, organization and terminology.* The plan has a table naming
which app each user-facing decision copies (Keynote, Pages, Google Docs). Apply
that test to any new UI here.

**Open questions from A5, not fixed** (full list in the plan's "Findings for
Ethan"): song editing has **no autosave and no journal at all**
(`SongEditorModal` keeps its own dirty flag over the separate `songs` table) —
wants its own plan; and `default_background_id` is **dead**, hard-nulled by
`normalizePresentation` on every path, which is the real cause of the
`CLAUDE.md` known issue about older rows.

## 4. Conventions the code now follows

- **Colours:** tokens in `src/styles/globals.css` (`--bg-surface`,
  `--text-primary`, `--accent`, `--on-dark-1..11`, …). Tailwind 4 `@theme`
  names every token after itself: `bg-bg-surface`, `text-text-primary`,
  `border-border-subtle`, `text-accent`, `bg-home-cta-gradient`;
  `src/__tests__/tailwindTokens.test.ts` fails on drift. Alpha variants use
  opacity modifiers (`bg-accent/12`, `border-white/18`), which Tailwind 4
  compiles to `color-mix` and which proved pixel-exact. Hex literals in JSX
  are banned by ESLint (`no-restricted-syntax`); data palettes live in
  `src/utils/colorPalettes.js` and `templateVisuals.js`.
- **Tailwind 4 specifics:** `@import 'tailwindcss' source(none)` with
  explicit `@source` lines; app element resets live in `@layer base`
  (an unlayered `* { padding: 0 }` beats every layered utility);
  `--text-*--line-height` pinned to v3's rem values; `@custom-variant hover (&:hover)`;
  base rules restore the pointer cursor on buttons and the v3 placeholder
  colour. Renamed utilities: `rounded-sm` (= old `rounded`), `shadow-sm`,
  `blur-sm`, `outline-hidden`. Any spacing number now works (v3 silently
  dropped off-scale ones). When renaming utilities by script, **scope to
  class strings** — a broad regex once renamed a `.blur()` call.
- **Inline styles:** only dynamic values (`style={{ width }}`), split off from
  static ones. `text-xs` also sets line-height; replacing an inline size next
  to it needs `text-[Npx] leading-4`. `font-[monospace]`, not `font-mono`;
  `[word-break:break-word]`, not `break-words`. Animations/transitions cannot
  be seen by captures — read the built CSS instead.
- **Hover:** `hover:` classes; a base background that is an inline dynamic
  value beats any `hover:` utility, so the base condition moves into the
  class string. `HOVER_HANDLER_BUDGET` in `inlineStyleBudget.test.ts`.
- **React:** derive-don't-sync; adjust-state-while-rendering hooks
  (`useCollapsedSections`, `useClearWhenMissing`); `useLatest` for
  subscription handlers; the editor store owns the auto-edit decision
  (`resolveSelectionEditing`). DOM test hooks: `data-slide-editing`
  (the slide being edited, not the inline editor), `data-slide-text-editor`,
  `data-selected`, `data-backdrop`, `data-context-menu`, `data-profile-card`,
  `data-panel="song-library|media-library"`, `data-resize-handle`.
- **IPC:** `shared/ipcContract.ts` is the single source of truth; renderer
  goes through `src/utils/ipc.ts` only (a guard test forbids `window.electronAPI`
  elsewhere, except E2E specs which call it deliberately). Media is served
  through the `presenterpro-media:` scheme.
- **CSP:** injected at build by a Vite plugin in `electron.vite.config.js`;
  `style-src 'unsafe-inline'` stays until the dynamic inline styles go.
  `e2e/csp.spec.ts` collects console errors from all three windows.

## 5. Recipes

- **Start a plan:** measure first (counts, versions, what the net sees),
  write `tasks/plan-<id>-<name>.md` (Measured / Decisions / Anti-weakening
  clause verbatim / Blast radius / Todos / Findings), then execute.
- **Land a PR:** gate + format:check → commit with explicit paths → push →
  `gh pr create` with Summary / Proof / Findings → wait for both required
  checks → `gh pr merge N --squash`. A poll loop that merges when green is
  fine; assert the PR number is non-empty first (an empty `$N` once merged
  the current branch's PR with subject `(#)`).
- **Dependabot:** safe minors merge as-is once green (comment
  `@dependabot rebase` after main moves). If `npm ci` fails on its lockfile,
  `npm install --package-lock-only --ignore-scripts` on the branch and push.
  Majors held by peer ranges get an ignore rule in `.github/dependabot.yml`
  with the reason.
- **A visual change on purpose:** make it, dispatch `update_baselines`,
  commit only the baselines that changed (compare with `cmp`), and say in
  the PR which captures moved and why.

## 6. Traps that cost real time

- `workflow_dispatch` inputs are validated against the **default branch's**
  workflow file: land a new input on `main` first.
- `gh pr merge --delete-branch` deletes the local branch and checks out
  `main` mid-chain; rebase by SHA afterwards.
- Fetch before branching; a stale `origin/main` produced two conflicts.
- Playwright: destructure the window as `{ window: page }`; menu items carry
  their shortcut in the accessible name (`Keyboard Shortcuts ?`); the `?`
  shortcut yields while a text box is selected; inserting a library song
  and choosing a media action close their panels themselves.
- A fresh profile is not empty: main seeds a presentation and the renderer
  seeds hymns ~1s after load (and Ethan wants them kept).
- E2E teardown is `app.exit(0)` + wait; never `app.close()`.
- Commitlint rejects non-conventional types and sentence-case subjects;
  headers over 100 chars only warn.
- **`closeApp(launched)` DELETES the throwaway profile** unless you pass
  `{ keepUserData: true }`. Seeding a database between two launches fails with
  "unable to open database file" otherwise, which reads like a product bug.
- **A local `VISUAL=1` run proves nothing about the committed baselines.**
  `playwright.config.ts` sends non-CI runs to the gitignored
  `.local-snapshots/`, so a bare run compares against nothing. The only local
  proof is laptop-vs-laptop: capture on the base tree with `--update-snapshots`,
  apply the change, re-run with `VISUAL_STRICT=1`. **And run a base-vs-base
  control before believing any local diff** — `tutorial.png` drifts ~4,300 px on
  this laptop either way. CI is the verdict.
- **`no-unused-vars` does NOT flag unused *exported* bindings.** When a plan
  removes symbols, verify with `grep`, not with lint — lint only catches the
  now-dead imports and locals they leave behind.
- **Two `set()` calls means two subscriber notifications.**
  `insertNewSlideIntoCurrentPresentation` and `TitleBar.commitRename` both call
  `setPresentation` (which resets `isDirty` **and** `requiresInitialSave`) and
  *then* `setDirty(true)`. Any store subscription that needs "changed AND dirty"
  must use A2's disjunction — `!prev.isDirty || state.presentation !== prev.presentation`
  — or it silently never fires for the two commonest edits.
- **Do async work AFTER setting store flags, not before.** A5 added IPC round
  trips inside `openPresentationInEditor` ahead of `markPresentationFreshOpen()`
  and lost a race on CI: a quit landing in that window saw a clean document and
  skipped the Unsaved Changes gate entirely.
- **Have a fresh agent review any substantial plan before writing code.** Two
  independent reviews of the A5 plan found four real blockers, including an
  autosave condition that would never have fired. It cost minutes and saved a
  day.
