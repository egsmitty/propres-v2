### What A6 is, in one page

Ethan, 2026-09-11: *"once i make a save i cant revert to last save. not sure
that makes sense to me, it should be a version history with memory that isnt too
long but useful enough, an undo can revert well enough."*

He is right: `File ▸ Revert to Last Save` is gated on `isDirty`, so it greys out
the moment you save — exactly when you would want it. It is really "discard
uncommitted changes", and `⌘Z` already covers that at a finer grain. The data
for the real feature already exists: `presentation_versions` is append-only.

His decisions:

| Question | Answer |
|---|---|
| Keep `Revert to Last Save`? | **Keep both** — it stays the one-click discard; Version History does the rest. Apple's model (`Revert To ▸ Previous Save` / `Browse All Versions…`). |
| Retention | **Time-thinned** — every save from today, then one per day for ~30 days (replaces A5's flat cap of 25). |
| Is restoring undoable? | **Yes** — restoring first saves the current state as a version. |

**THE INVARIANT, which everything in A5 and A6 rests on:** *the newest version
row always equals the committed state of the presentation row.* Break it and two
things happen on the happy path — every affected presentation opens "Unsaved
changes" forever (`openPresentationInEditor` derives the dirty flag by comparing
row against newest version), and `Revert to Last Save` restores the thing you
just restored away from. So every operation ends by appending the state it left
the row in. The plan's first draft broke this and was rewritten; there is a test
(`isDivergedFromLatest` is false after `restoreVersion`).

Other load-bearing points from the plan: `captureVersion` must now **return a
boolean** and callers abort on `false` (a failed version write followed by an
overwritten document, silently, is the feature failing at the only moment it
matters); `revertToLatestVersion(id, { capture })` takes `capture: false` for
Discard, because Discard means *this never happened* and must not append a
version of the work being thrown away; and Version History is **disabled while
presenting** — restoring mid-service can leave `PresenterPanel` with
`liveIdx === -1`, where the next spacebar jumps the congregation to slide 1.

## 4. The save model (plans A5 + A6) — read before touching saves

`tasks/plan-A5-autosave.md`, then `tasks/plan-A6-version-history.md`.

| Concept | Lives in | Changed by |
|---|---|---|
| Live document | the `presentations` row | autosave, save, revert, restore |
| Versions (restore points) | `presentation_versions` (migration 5) | manual save, open-if-none, revert/restore |
| In-memory document | `useEditorStore.presentation` | every edit |

- Edits **autosave** to the presentation's own row a couple of seconds after
  typing stops.
- **`isDirty` means "the live row differs from the newest version", and autosave
  never clears it.** Only Save (which appends a version) and Revert/Restore may.
- Versions are **append-only**, and **newest is `id DESC`, never `saved_at`** —
  `unixepoch()` is second-resolution, so two saves in one second would tie.
- The A2 crash-recovery journal's **writer is gone**: autosave bumps
  `updated_at`, so `selectRecoverable` would call every journal row stale before
  reading it. The table, migration and `offerRecoveryOnStartup` remain only to
  drain profiles written by older builds.
- **Saving must not reload the document** — see #109. Use `syncSavedPresentation`,
  not `setPresentation`, which means "load a different document" and resets
  selection and undo history.

**Why the UI looks the way it does:** Ethan's product thesis — *mirror
successful apps in almost everything; spend the novelty budget only on
church-service focus, organization and terminology.* The A5 plan has a table
naming which app each user-facing decision copies (Keynote, Pages, Google Docs).
Apply that test to any new UI here.

## 7. Conventions the code follows

- **Colours:** tokens in `src/styles/globals.css` (`--bg-surface`,
  `--text-primary`, `--accent`, `--on-dark-1..11`, …). Tailwind 4 `@theme` names
  every token after itself: `bg-bg-surface`, `text-text-primary`,
  `border-border-subtle`, `text-accent`, `bg-home-cta-gradient`;
  `src/__tests__/tailwindTokens.test.ts` fails on drift. Alpha variants use
  opacity modifiers (`bg-accent/12`, `border-white/18`), which Tailwind 4
  compiles to `color-mix` and which proved pixel-exact. Hex literals in JSX are
  banned by ESLint (`no-restricted-syntax`); data palettes live in
  `src/utils/colorPalettes.js` and `templateVisuals.js`.
- **Tailwind 4 specifics:** `@import 'tailwindcss' source(none)` with explicit
  `@source` lines; app element resets live in `@layer base` (an unlayered
  `* { padding: 0 }` beats every layered utility); `--text-*--line-height` pinned
  to v3's rem values; `@custom-variant hover (&:hover)`; base rules restore the
  pointer cursor on buttons and the v3 placeholder colour. Renames:
  `rounded-sm` (= old `rounded`), `shadow-sm`, `blur-sm`, `outline-hidden`. Any
  spacing number now works (v3 silently dropped off-scale ones). Renaming
  utilities by script must be **scoped to class strings** — a broad regex once
  renamed a `.blur()` call.
- **Inline styles:** only dynamic values (`style={{ width }}`), split off from
  static ones. `text-xs` also sets line-height; replacing an inline size next to
  it needs `text-[Npx] leading-4`. `font-[monospace]`, not `font-mono`;
  `[word-break:break-word]`, not `break-words`. Animations and transitions
  cannot be seen by captures — read the built CSS instead.
- **Hover:** `hover:` classes; a base background that is an inline dynamic value
  beats any `hover:` utility, so the base condition moves into the class string.
- **React:** derive-don't-sync; adjust-state-while-rendering hooks
  (`useCollapsedSections`, `useClearWhenMissing`); `useLatest` for subscription
  handlers; the editor store owns the auto-edit decision
  (`resolveSelectionEditing`). DOM test hooks: `data-slide-editing`,
  `data-slide-text-editor`, `data-selected`, `data-backdrop`,
  `data-context-menu`, `data-profile-card`,
  `data-panel="song-library|media-library"`, `data-resize-handle`.
- **IPC:** `shared/ipcContract.ts` is the single source of truth; the renderer
  goes through `src/utils/ipc.ts` only (a guard test forbids
  `window.electronAPI` elsewhere, except E2E specs, which call it deliberately).
  Media is served through the `presenterpro-media:` scheme.
- **CSP:** injected at build by a Vite plugin in `electron.vite.config.js`;
  `style-src 'unsafe-inline'` stays until the dynamic inline styles go.
  `e2e/csp.spec.ts` collects console errors from all three windows.
- **Renderer commands** are centralized in `src/utils/appCommands.js`;
  load/save/open helpers in `src/utils/presentationCommands.js`; background
  inheritance in `src/utils/backgrounds.js`.

## 8. Recipes

- **Start a plan:** measure first (counts, versions, what the net sees), write
  `tasks/plan-<id>-<name>.md` (Measured / Decisions / Anti-weakening clause
  verbatim / Blast radius / Todos / Findings / Compliance Manifest), have a
  fresh agent review it, then execute.
- **Land a PR:** gate + `format:check` → commit with explicit paths → push →
  `gh pr create` with Summary / Proof / Findings → wait for **both** required
  checks → `gh pr merge N --squash`. A poll loop that merges when green is fine;
  assert the PR number is non-empty first (an empty `$N` once merged the current
  branch's PR with subject `(#)`). Delete the branch after merging — squash-merge
  hides that it is merged.
- **Dependabot:** safe minors merge as-is once green (comment
  `@dependabot rebase` after main moves). If `npm ci` fails on its lockfile,
  `npm install --package-lock-only --ignore-scripts` on the branch and push.
  Majors blocked by peer ranges get an ignore rule with the reason.
- **A deliberate visual change:** make it, dispatch `update_baselines`, commit
  only the baselines that moved, and say in the PR which ones and why.

## 9. Traps that cost real time

- **`workflow_dispatch` inputs are validated against the default branch's**
  workflow file: land a new input on `main` first, then dispatch on the branch.
- `gh pr merge --delete-branch` deletes the local branch and checks out `main`
  mid-chain; rebase by SHA afterwards. Fetch before branching — a stale
  `origin/main` produced two conflicts.
- **`closeApp(launched)` DELETES the throwaway profile** unless you pass
  `{ keepUserData: true }`. Seeding a database between two launches otherwise
  fails with "unable to open database file", which reads like a product bug.
- **A local `VISUAL=1` run proves nothing about the committed baselines** — it
  writes to the gitignored `.local-snapshots/`. The only local proof is
  laptop-vs-laptop, and **run a base-vs-base control before believing any local
  diff**: `tutorial.png` drifts ~4,300px on this laptop either way. CI is the
  verdict.
- **`no-unused-vars` does NOT flag unused *exported* bindings.** When a plan
  removes symbols, verify with `grep`, not with lint.
- **Two `set()` calls means two subscriber notifications.**
  `insertNewSlideIntoCurrentPresentation` and `TitleBar.commitRename` both call
  `setPresentation` (which resets `isDirty` **and** `requiresInitialSave`) and
  *then* `setDirty(true)`. Any store subscription that needs "changed AND dirty"
  must use A2's disjunction —
  `!prev.isDirty || state.presentation !== prev.presentation` — or it silently
  never fires for the two commonest edits.
- **Do async work AFTER setting store flags, not before.** A5 put IPC round
  trips inside `openPresentationInEditor` ahead of `markPresentationFreshOpen()`
  and lost a race on CI: a quit landing in that window saw a clean document and
  skipped the Unsaved Changes gate entirely.
- **`data-slide-editing` means the text box is selected, not that a caret
  exists.** The contentEditable mounts only on a double-click, so E2E typing
  must wait for `[data-slide-text-editor="true"]` first or it types into nothing.
- A fresh profile is not empty: main seeds a presentation and the renderer seeds
  four hymns ~1s after load — and Ethan wants them kept.
- E2E teardown is `app.exit(0)` + wait for exit, never `app.close()`; never call
  `app.process()` after exit; wait for `firstWindow` before any `evaluate`.
- Playwright: destructure the window as `{ window: page }`; menu items carry
  their shortcut in the accessible name (`Keyboard Shortcuts ?`); the `?`
  shortcut yields while a text box is selected; inserting a library song and
  choosing a media action close their panels themselves.
- Commitlint rejects non-conventional types and sentence-case subjects; headers
  over 100 chars only warn.
- **Committing from a `git worktree` fails in the `commit-msg` hook.** Husky
  passes an absolute `COMMIT_EDITMSG` path and commitlint resolves it against
  the worktree root, producing a doubled path and `ENOENT`. `HUSKY=0` does not
  skip it. For a commit that touches nothing under `presenter-pro/`,
  `git commit --no-verify` is the way through — check the message against the
  conventional format by hand. Commit from the main checkout when the change is
  code, so the hooks actually run.
- Never run foreground git while a background job may hold `index.lock`, and
  never `rm index.lock` blind — it corrupted the index once.
- Grep hits are leads, not verdicts. Two GitHub issues looked unimplemented
  until the code was actually read.
- A stray, nearly empty `node_modules/` sits at the **repo root** (it holds only
  `.vite`) — an `npm install` run one directory too high. Harmless, untracked,
  safe to delete; do not mistake it for the app's `presenter-pro/node_modules`.
